## Invariants and non-goals

- Keep the original URLs, recipe/rate boundaries, machine-rank policy, technology, belt domains, capacities and physical predicates.
- Keep content-derived final frames with the existing0–4 added-row candidates. Routing capacity never becomes an emitted padding promise.
- Keep the original parent deadline and shared routing expansion ledger. Hierarchy completion still uses `PlacementCompletionDeadlines(deadline, deadline, None)`. Slots and final certification retain their existing atomic behavior; do not claim a hard interruptible wall.
- Keep `_COMMIT_REPAIR_PASSES=3`, existing RRR/stale limits, bounded CBS/member limits and its one-invocation gate. No additional outer settlement/repacking loop.
- A provisional `bool`, complete path count, successful commit, or partial candidate is not a completed factory. Only the existing `PlacementCompleted` can authorize hierarchy success.
- No new global corridor allocator, child scheduler, bus, per-primitive finalization, unrelated module split or cross-build cache.
- Preserve all original refusal populations. No baseline failure is silently reclassified as proof of impossibility or as a successful factory.

## Architecture and ownership

```text
existing selection/search
  -> incremental prospective frame checks
  -> ordinary probe / existing optional connector graph
  -> existing disposable commit_once workspace
  -> complete paths AND no reservation deficit?
       no: partial diagnostics only
       yes: compose-owned settlement
              power -> global slots -> certified cleanup -> actual frames -> certification
              completed: carry the exact accepted object to strategy
              refused: contextual evidence -> existing bounded repair
              cancelled: budget/inconclusive; no geometry exclusion
```

`routing_domain` owns route choices, staging, expansion accounting and bounded repair. `RoutePrimitives` owns physical connector witnesses. `hierarchy.compose` supplies the hierarchy-specific settlement callback. `finalize` remains the sole cleanup/projection/certification owner. `hierarchy.strategy` supplies the actual composed spec and consumes the accepted result rather than rebuilding it.

### A. Incremental prospective selection

Retain `_CompositionProjection.allows_buildings(candidates, *, committed=(), deadline=None) -> bool` and its sole production entry through `_Canvas.projected_buildings_are_clear`. This is explicitly prospective, not certification.

Intern owner-local ordered prefixes of full `PlacedBuilding` records. Each selection node retains its parent/member, children, an exact extent handle and completed per-`_JunctionProjectionFrame` verdicts. Preserve order, duplicates and attachment identity. The root owns immutable canvas inventory, reserved power, policy, rules and the existing root cleanup state.

An extent handle contains its parent, the precise normalized linkless member which the current `_cleanup_snapshot_with_linkless_static` would append, and completed survivor bounds. A member inside the current exact bounds inherits the handle. For a novel growth handle, reconstruct a transient root-plus-expansion-chain graph and run the existing authoritative bounds operation. Retain only completed bounds, not the extended `_CleanupSurvivorGraph`; discard graph copies after evaluation. Key this initially by the exact expansion chain, not equal rectangles. Retaining every existing snapshot would copy base-sized arrays per growing prefix and is explicitly prohibited.

For an exact requested frame, reuse the longest completed prefix and evaluate its suffix with existing `_member_clear` and `_pair_clear` arithmetic/order. Keep `allows` calling `_frame_clear(additions, frame)` with the existing signature; incremental frame evaluation lives behind that seam. The existing common-frame and extent-expansion tests replace this predicate to exercise observable behavior and must remain effective. One common frame must satisfy the entire selection. A false prefix verdict applies only to that exact frame; adding/removing a member can change reachable frames and requires rechecking earlier members there. Link normalization is solely for bounds calculation, never geometry identity.

Cancellation is checked before every cache answer and before publishing newly computed state. An interrupted suffix cannot publish a false verdict or a successful full-prefix verdict. Previously completed independent prefix facts may remain. Rip-up selects another prefix; no rollback of shared mutable selected geometry is necessary. Frame-free existence checks remain on the complete node, never on the union of per-member possibilities.

Retained state is the immutable root plus distinct prefix/extent nodes and evaluated node/frame facts. Novel extent evaluation still costs O(base inventory + growth chain) transient work; this is not allocation-free. Measure prefix sharing, distinct extent/frame states, retained bytes and allocation churn on both captures. Release all state with its owner. Do not deep-hash a factory per prospective query. Direct union of cleaned bounds can miss retained base belts; a four-extrema shortcut requires separate exact-oracle proof and is not part of this design.

### B. Demand-driven optional connectors

Keep `_search` as scheduling owner and `RoutePrimitives.edges` as the existing bounded witness generator. No Python-only lazy provider: native A* snapshots all extra edges before its loop, and ordinary ALT cannot remain valid after unannounced shortcut insertion.

Use at most one ordinary probe per `_search` invocation, before the first of its existing five admission attempts. Ordinary success still passes the same body/source/selection checks; rejection consumes the existing admission attempt, then uses enriched search on the remaining attempts. Ordinary no-path does not create an additional admission retry.

At ordinary-to-enriched transition, restore applicable original source/destination offers and recompute the graph context before generating connectors. An ordinary whole-selection refusal must not remove every start for its tap from enriched search: added connector members can change reachable frames. Keep applicable body-local invalidity separate from contextual refusal and from temporary positive proposal restrictions. Ordinary-context rejections consume their existing slot but cannot become source-wide/cell-wide bans in the changed graph.

Let `M = _MAX_EXPANSIONS` (currently200000), `R = M + 1`, incoming immediate allowance `L = search_budget["left"]`, and private probe allowance `Q = min(M + 1, max(0, L - R))`. Skip the probe when `Q < 2`; small-budget cluster calls go directly to enrichment. This preserves one enriched attempt's full native node allowance, not all retries or all later nets. The native per-attempt cap remains M. The scheduler can execute one additional bounded search attempt, paid from the unchanged shared ledger.

If a parent deadline D exists, sample t and set the ordinary deadline to `t + (D-t)/8`; do not probe if D has expired. Poll every64 expansions during that subcall using an optional `_astar(..., deadline_check_every=None)` keyword, forwarded to the existing native `deadline_every` and Python loop. All subsequent enumeration/search uses the unchanged D. No deadline means expansion-only probing. Polling and allocation are not hard real-time bounds. A nonzero speculative probe cannot mathematically preserve every old deadline-bounded success; measure the capability controls and originals before promotion.

The ordinary subcall uses the same endpoints/grid/ownership/technology/forbidden constraints, `extra_edges=None`, and `blame=None`. Do not publish an ordinary sealed pocket as physical impossibility or let it alter blame before enrichment. Debit the immediate `search_budget` exactly once by `Q - private['left']`, never by `result.expansions` and never directly against the closed-over outer `budget`. In cluster search, `_cluster_search` alone transfers total consumption of its private search allowance back to the outer ledger once. Raw telemetry still sums both attempts and all admission retries. Cap/deadline stops can report one more expansion than they debit. A subdeadline or private-budget stop falls through to enrichment if the immediate budget and parent deadline remain live. Empty/partial connector enumeration and enriched no-path stay inconclusive as today.

The full native-sized probe is deliberate: measured successful ordinary searches reach101679 and121579 expansions. A32768 cap catches only20/23 and21/25 of those observed paths, forcing costly enumeration on several known ordinary routes. This is a starting schedule, not a tuned optimum.

### C. Complete candidate and provenance

`commit_once` already builds all route belts and links on `canvas.clone()` before repair state disappears. Change its internal return into an owned attempt containing materialized workspace, physical ownership, existing commit failures and optional settlement result. Invoke settlement only after a successful physical commit with every required net selected and no missing port reservation. Zero required nets is a complete selection and must not bypass settlement.

The callback consumes the actual committed workspace and ownership, captures the actual composed `BuildSpec`, policy, belt rules and original deadline, and runs the existing infill, `_place_power`, global `assign_sorter_slots`, `prepare_placement_completion` and `complete_placement`. No transform touches the live routing canvas. Retain current partial diagnostic infill behavior in compose, separately and without a completion handle; its failures never inflate unrouted-cut counts.

Use candidate-original indices as stable identity within one attempt, not object identity or coordinates. Base indices map to actual `BlockPlaced`/local indices. Expose ownership while `_commit_paths`, `RoutePrimitives.emit` and source/sink attachment code append or mutate records. Each building has a set of causal `NetId` owners; unchanged base objects have no invented owner. Shared source/sink junctions include every dependent sibling, not merely the last writer. Record dependencies of bypassed links and already-emitted attachments as well as append spans. Co-located connector attachments retain distinct indices. Power records carry the complete contributing owner set; if causality is unavailable, mark the conflict candidate-global rather than assigning the nearest route.

Ownership is an index-aligned `tuple[frozenset[NetId] | None, ...]`: an empty set means known no route cause; `None` means unknown/candidate-global, never identity or known-empty. Shared mutations and read dependencies union known causal owners; an unknown contributor stays unknown. This distinction must survive cleanup and power siting.

Finalizer lineage is final-index -> candidate-input-index. Extend `BoundaryCompactionResult` and all candidate-bearing ready/refused/completed/invalid/certification-expired results with accepted survivor mapping; `None` denotes the exact identity map, not missing information. Additionally expose sparse accepted link-dependency records: survivor original index, input/output side, and traversed original indices. `_remove_buildings` has both the survivor sequence and removed link chain; a survivor map alone loses the latter's causes. Compose mappings and bypass dependencies only across accepted structural/side transforms, translating each step through prior lineage and unioning inherited dependency chains. Rejected proposals contribute neither; fallback from the original resets mapping/dependencies to identity/empty. Cancellation publishes no fabricated partial lineage. Routing maps these original indices to causal owner unions.

Add frame-contextual witnesses alongside, not instead of, the existing aggregate `ProjectionRefusal.failures`: each witness records the exact `FrameCandidate`, actual `planet.Projection` and original `ProjectionFailure`. These are created in the authoritative projection loop, not reconstructed from the band or two cells. Materialization preserves list order; compose the accepted cleanup map to recover candidate originals. Keep report reuse bound to identical physical placement, as today.

### D. Sound contextual repair

The existing `retain_commit_failures` installs unconditional endpoint/path-cell bans. Settled projection evidence MUST NOT enter that branch. The existing combined prospective-selection rejection in `_commit_paths` must also be classified as contextual instead of banning every selected tap.

Keep ordinary applicable commit failures on the current path. Store contextual rejection separately with the exact ordered route selection, source/sink hints, taps, connector witnesses, immutable packed/spec/rule/policy context, accepted survivor/link state, infill state and frame witnesses. Use object-owner sets to select participants plus source/destination companion closure for the existing three repair passes. Candidate-global failures remain honest refusals if no bounded participant can be identified. Do not project world collision coordinates into lattice walls or pretend a rejected layout is a sealed pocket.

The proposal unit is an implicated existing source attachment/tap offer group, existing destination-hint group, or existing companion reroute, with frozen other choices and the current canonical connector graph. First try normal routing. In remaining existing admission/commit/CBS slots, try an already-exposed alternate source group, then destination group or companion reroute, in current deterministic offer order. Re-query endpoint offers after staking changes. A positive source/goal restriction selects one branch; it is not a learned ban on omitted offers. Omitted choices remain unsearched/inconclusive. No new same-edge model catalog, mandatory-macro-edge solver, forced extent waypoint, pass count or outer loop is introduced.

Record no-goods only for an exact whole deterministic choice under unchanged other choices, offers/hints/taps, canonical witnesses, grid/guard/ownership, packed/spec/rules/policy context; otherwise retain the exact full materialized candidate refusal. Graph, offer and companion changes reactivate applicable choices. Never deduplicate settlement by tap/stack/extent signature: ordinary belts can change links, slots, power, cleanup and survivors. For repeated-settlement avoidance, use the full ordered linked/infilled/globally-slotted candidate plus all finalizer-relevant placement metadata, spec, policy, rules and provenance. Check cancellation before reuse; partial computation and budget stops create no negative entry. Earlier route-choice equality is usable only after deterministic materialization is established.

An exact-path prefix automaton is a conditional alternative, not a prerequisite or part of the unconditional implementation plan. It can exclude one walk without banning shared cells, but a different walk need not move the convicted Splitters or actual frame. Consider native/Python product-state work only if a real same-context path-only alternative demonstrably changes settlement under unchanged clocks and simpler existing attachment proposals cannot reach it. A tiny shared-cell graph proves algorithmic correctness, not factory value.

Give existing CBS cluster construction explicit contextual participants, not forged lattice wall cells. Recheck each proposed complete result with the same owned settlement callback. Contextual exclusions, changed-context refusals and cancellation cannot support `PROVED`, exhaustive placement relations, or an unconditional `ClusterRelationNoGood`. Do not extend cluster size, invocation count or solved-then-commit retry count.

If the existing finite choices cannot move the convicted cause or authoritative surviving frame, return an honest refusal. Production strategy calls compose once; its earlier recut loop handles unsolved children, not settled composition failures. There is no existing settled-refusal-to-next-pack continuation. Adding one violates this design's no-new-outer-loop constraint and needs a separate architectural decision.

### E. Single success publication

Add a typed optional settlement outcome to `DetailedRouteResult` and `ComposeResult`. The successful payload carries the existing `PlacementCompleted` and infill counts. Expected refusal/cancellation variants preserve their actual causes and source phase. Absence means no complete settlement was performed, never success. Keep shared routing types independent of hierarchy imports; use TYPE_CHECKING for finalizer annotations where necessary.

All success exits of `_route_all`, including focused repair and CBS, pass the immediately accepted attempt to `_finish`. An accepted complete exit does not run `_commit_paths` again. Callback presence alone is not enough to skip materialization: a partial/budget/stranded final exit retains the existing selected-incumbent `_finish` commit path, permanent-guard reset, hints/taps, unlinked failures and original counts, then compose's partial diagnostic infill. It invokes no full settlement and carries no completion. Do not cache successful handles across route mutations or attach a last-round handle to an earlier best-round incumbent. An accepted atomic certification is not subjected to a new post-certification expiry check.

In strategy, compute `composed_spec` after allocation and before compose, outside the broad crash guard. Split the original guarded boundary/allocation and compose calls around this unguarded computation, preserving their original refusal classifications. Unexpected `composed_spec` exceptions still propagate. Pass the result separately as required `settlement_spec`; retain requested `spec` for existing packing decisions. On success remove the old strategy slot/prepare/complete pass and consume the exact completed placement/report. On partial/refused/cancelled outcomes refuse explicitly. Keep raw packed block coordinates identified as routing provenance, not indices into the cleaned/framed success placement.

Moving the callback must not silently widen the broad composer crash guard. Expected infill/slot/projection/validation/cancellation outcomes become typed settlement outcomes. Unexpected settlement exceptions are carried only across that existing guard and re-raised outside it, retaining their original traceback; do not swallow them as generic composition-crashed refusals. This bridge carries `Exception`, not an untyped error dictionary, and never catches process-control `BaseException` as a normal outcome.

Freeform calls `_route_all` without a settlement callback and keeps its existing finalization ownership. Freeform and sequence_solver completion clocks do not change when shared lineage fields are added. Direct compose callers must supply an actual settlement spec. Diagnostic scripts are migrated explicitly or retained with their frozen source snapshots; no old-API production aliases.
